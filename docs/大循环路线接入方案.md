# 大循环路线接入改造方案

> 状态：**已实施**（全项目 lint 零错误，拍平结构 / 晋级链 / 熏听系数已经 node 脚本验证）
> 范围：qingba2.0 微信小程序全量（数据层 + 11 个页面）
> 数据源：`qingba_big_loop_route.json`（官方原始叙事结构存档；运行时读取 `utils/bigloop_route.js` 的格式化终稿，修改数据时两者同步）

## 实施记录（与方案文的差异补充）

- **新增文件**：`utils/bigloop_route.js`（原始数据内嵌 + 拍平转换：双轨清洗 / 资源形态转换 / prev 链 / 字段补齐 / tips 按内容拆到小段）。
- **阶段数修正**：拍平后为 **9 个阶段**（`big_loop_2` 本身不再是阶段，拆为其 6 个小段，3 顶层 + 6 小段 = 9；方案初稿误写为 10）。
- **支线提示落地**：stagePicker 复用 radio-list 组件既有的 `desc` 槽显示「可选支线」说明，route 页节点虚线样式 + 名称旁「可选」徽标，均未引入图标资源。
- **晋级推进链化**：`stage.js` 的 `doPromote` 原按 `stageIndex + 1` 推进，调整牛3（数组末位）会被误判为终点；已改为 `findNextStage`（沿 `prev_stage_ids` 找），主线优先、支线内顺序正确，终点（常规准桥梁 / 大循环三阶段 / 调整牛3）统一走「完成阶段」。
- **阶段晋级准入放开**：`isRegularStage` 限制移除，大循环阶段（含调整支线）同样可晋级；支线小段无 `target_phase`，自动走「直接确认」分支，符合官方无固定测试档位的语义。
- **实施中额外发现并修复**：`settings.js` 模块顶层的 `stageOptions`（加载时执行一次，切路线不刷新）、`home.js` `Page.data` 静态首末阶段名（同因）、`utils/customResources.js` 的 `_getStage` 写死单路线（大循环自定义资源会查不到，改为全路线查找）、`stats.js` onShow 路线变化检测（切路线返回统计页时整体重建选择器）。

## 一、背景与目标

- **现状**：App 只支持「常规路线」（常规1-6 + 准桥梁共 7 个阶段），数据源为 `utils/data.js` 中的 `routeData` 单例，11 个页面全部直接引用。
- **目标**：接入「大循环路线」（第二阶段 6 个小段拍平为独立阶段，加上其余 3 个顶层阶段，**拍平后共 9 个阶段**），用户在设置页切换路线。
- **全局口径（已拍板）**：**所有页面只服务当前路线**。打卡记录、统计、补录、编辑、目标设置、我的资源全部跟随当前路线；想看另一条路线的数据，去设置切换。切换时 toast 轻提示「已切换至大循环路线，打卡与统计将展示该路线数据」。

## 三、核心设计：路线注册表

### 3.1 注册表结构

```js
// utils/data.js
const ROUTES = {
  regular: { id: 'regular', name: '常规路线', stages: [/* 现有 7 阶段 */] },
  bigloop: { id: 'bigloop',  name: '大循环路线', stages: [/* 拍平后 9 阶段 */] },
};
// routeData 由常量改为 getter，按 storage 中的 current_route 返回对应路线
```

- 新增存储键 `current_route`；未设置时默认 `regular`（老用户零感知）。
- 各页面引用点从 `routeData.stages` 换成 `getCurrentRoute().stages`，机械替换。

### 3.2 大循环 JSON 拍平转换

- **阶段拆分**：`big_loop_2` 的 `sub_stages` 提升为独立 stage，最终 10 个：
  `big_loop_pre` / `big_loop_1` / `big_loop_2_adjust_niu1~3` / `big_loop_2_standard_niu4~6` / `big_loop_3`。
- **字段映射补齐**（拍平层一次性完成，route 展示与 picker 快照共用）：

| JSON 原字段 | 目标字段 | 说明 |
|---|---|---|
| `sub_stage_id` | `stage_id` | |
| `sub_stage_name` | `stage_name` | 自带「调整策略/标准策略」前缀，天然区分 track |
| `target`（如「积累到1000词」） | `vocabulary_target` | 缺失会导致 home 显示空白 |
| — | `target_phase` | 补齐占位，避免 `route.wxml:56` meta 行硬拼接渲染成「· · 建议90小时」 |
| `mandatory`（false = 支线） | `optional` | 供 route 页支线态与徽标使用 |
| — | `prev_stage_ids` | 晋级链声明（见第六节） |
| — | `listening_audio: []` | 熏听分组空占位，沿用现有 forEach 逻辑覆盖大循环 stages |

- **小小优趣双轨制统一（已拍板，v2 改为数据侧直写）**：全部只保留「新版 PhaseY」口径，与常规路线 `data.js` 现状一致。初版由运行时 `stripLegacyVersion` 正则清洗，v2 应产品要求删除该函数——RAW/json 文案已直接写成单轨终稿，数据即展示、无隐藏转换。
- **排序（已拍板）**：按官方晋级叙事排——前置→一→调整支线（牛1→牛2→牛3）→标准主线（牛4→牛5→牛6）→三阶段。顺序只影响展示，打卡与完成标记全按 stage_id、与数组位置解耦。
- **小段命名（已拍板，v3）**：stage_name = 阶段名 +（轨道缩写·牛几），即「第二阶段（调整·牛1）」「第二阶段（标准·牛4）」，与「第三阶段（牛7-9）」括号结构呼应。初版全名「第二阶段·调整策略（牛1小段）」因 stage_name 被 home 顶栏/统计选择器等十余处消费、过长挤压布局而废弃。支线在选择页只标「可选支线」，判定依据（一阶段测试结果）由阶段详情页 entry_requirement/promotion_standard 承载。
- **资源分组归一（已拍板；v3 终态：数据统一标准名 + ALIAS 机械字典）**：前置/二/三阶段的 RAW 与 json 的 category 统一为中文标准名——主线绘本/主线分级/主线动画/辅线分级/辅线动画/趣味拓展/融合App（官方同义变体「优选/入门/辅助」前缀、「辅线动画（原版-语速略快）」「融合App（可替代动画）」「优选绘本 | 准桥梁」后缀均在数据侧改名，无运行时同义归并）。GROUP_KEY_ALIAS 缩为 7 条「中文标准名→标准 key」固定字典（主线绘本→main_picture_books 等），toResources 恒定按字典换 key（useAlias 参数删除、表外直通），分组顺序（GROUP_ORDER）、名称（resourceLabels）、阶段页色点样式（rg-dot-<key>）与常规路线完全同源。第一阶段分组语义不同（核心素材主/替换版本等），key 即官方原名。历史自定义资源挂在旧变体 key 的不再迁移（字典已无变体条目）。
- **关键要点行内高亮（已拍板）**：tips 文本支持「**…**」标记标注重点（对应官方素材的红字标注），toKeyPoints 解析为 segments 片段，阶段页按片段行内渲染（--text 色 + 加粗）；text 字段保留去标记纯文本兜底。常规路线的整条级 highlighted 机制不变，stage 页归一层（withKpSegs）把两种结构统一为片段通道。前置阶段 tips 按官方素材 Page2/3 录入标注，并裁掉「前置阶段目标」「如何判断词汇量达标」「路径的三次选择」3 条（目标信息由阶段页顶部 vocabulary_target 承载，测试达标口径已由 promotion_standard 承载）。
- **数据终稿化重构（已拍板，v4）**：`bigloop_route.js` 删除 RAW 原始数据与拍平转换层（buildStages/normalizeStage/normalizeSub/toResources/TIPS_OWNERS 等），改为与常规路线 `data.js` 同构的格式化终稿——9 个阶段直接按运行时字段声明（resources 直用标准分组 key、素材 id=name、二阶段 tips 已按归属物理拆到各小段、journeyText 写死）。仅保留 `toKeyPoints/parseHiSegments` 文案标记解析（「**」标记比直写 segments 片段数组可读，文案改动零成本）。`raw` 导出删除（无消费方）；`GROUP_KEY_ALIAS` 保留导出（resources.js 历史自定义资源迁移用）。重构经与重构前 stages 快照逐字段 deep equal 回归，输出完全一致。

## 四、存储语义（四个决策点）

| # | 决策点 | 方案 |
|---|---|---|
| 1 | **current_stage 按路线存槽位** | 键拆为 `current_stage_regular` / `current_stage_bigloop`，切换路线互不污染；stagePicker 的 `setCurrentStage` 写入对应槽位 |
| 2 | **completedStages 全局混存** | 不拆槽位。两条路线 stage_id 命名空间天然隔离（`route_N` vs `big_loop_*`），各路线页面按自己的 stage_id 匹配，互不误伤 |
| 3 | **打卡记录按路线过滤** | **不给记录加 routeId 字段**，按当前路线 stage_id 集合判断，旧记录零迁移：<br>`const ids = new Set(route.stages.map(s => s.stage_id))`<br>`const monthRecords = checkin.getByMonth(ym).filter(r => ids.has(r.stageId))`<br>补录落库同样只写 stageId。空态文案改为「当前路线暂无打卡记录」 |
| 4 | **自定义目标 / 自定义资源** | 均按 stage_id 键存，天然按路线隔离，零改动零迁移 |

## 五、熏听折算

### 5.1 大循环系数表（定稿）

| 阶段 | 牛N 档 | 系数 | 依据 |
|---|---|---|---|
| 前置阶段 | — | **0** | JSON 原文「听音频效率低，可尝试听，但不计入时间」 |
| 第一阶段 | — | **0** | 已拍板。JSON 原文「听音频能力较弱，可不听音频」 |
| 调整·牛1 / 牛2 小段 | 牛1-2 | **0** | 与常规 regular_1/2 同档 |
| 调整·牛3 小段 | 牛3 | **0.5** | 与常规 regular_3 同档 |
| 标准·牛4 / 牛5 / 牛6 小段 | 牛4+ | **0.8** | 与常规 regular_4-6 同档 |
| 第三阶段（牛7-9小段） | 牛4+ | **0.8** | 与常规准桥梁同档 |

设计原则：**牛N 是两条路线共享的难度度量**，折算物理规则全局一致，用户切换路线无需重新理解规则。系数与 track（调整/标准）无关，只按牛N 定。

### 5.2 实现要点

1. `LISTENING_FACTORS` 直接把 10 个 `big_loop_*` key **合并进现有一张表**——命名空间不撞，`listeningFactor(stageId)` 一层查表，无需感知路线。
2. 0 系数的 `listeningTip` 文案改为通用表述（如「本阶段听音频可记录，但不计入有效时长」），大循环前置/第一阶段没有牛N，不能写「本阶段属于牛1-2 档」。
3. **factor 为打卡时固化的快照**：`addCheckin` 落库时写入，将来调整系数只影响新记录，历史记录口径不变（与常规路线现状一致）。
4. 大循环 stages 补 `listening_audio: []` 占位（3.2 节），否则阶段页熏听分组不出现。

## 六、晋级体系

### 6.1 大循环晋级拓扑（与常规路线的本质差异：分叉树）

```
前置阶段 ──测试p5+──▶ 第一阶段 ──测试p12+──┐
                                           │
             ┌───────── 测试结果分支 ◀─────┘
     [达标] ─┴─▶ 标准·牛4 ─p14+─▶ 牛5 ─p16+─▶ 牛6 ─▶ 第三阶段（牛7-9，终点）
     [不达标]─▶ 调整策略（可选支线，切入级别看测试结果，补足120H时间差）
                牛1 ─▶ 牛2 ─▶ 牛3 ─汇合─▶ 标准·牛4
                └─ 极端出口：补足仍不达标 → 官方建议「转常规」（设置切路线即可）
```

- App **没有任何自动晋级判定**（机制 = 阶段页展示 `promotion_standard` + 用户手动切换），分叉决策由家长完成，App 忠实展示即可 → 晋级/切换标准文本**零改动**。

### 6.2 completedStages 链式合并写入

**问题**：现有 `stagePicker.js:50-51` 按数组位置覆盖式写入前序标记；`route.js:61` 状态判定是「在名单里 **或** 数组位置在当前之前」双条件。大循环分叉结构下，无论数组怎么排，都会出现脏标（没走过被标完成）或错锁（走过却显示上锁）。

**方案**（三层）：

1. **数据层**：每个 stage 声明晋级链 `prev_stage_ids`。注意「调整小段互相不构成链」（JSON 原文：切入级别看测试结果）：

| 阶段 | prev_stage_ids |
|---|---|
| 前置 | `[]` |
| 第一阶段 | `[前置]` |
| 调整·牛1 / 牛2 / 牛3 | 各自均为 `[第一阶段]` |
| 标准·牛4 | `[第一阶段]` |
| 牛5 / 牛6 | `[牛4]` / `[牛5]` |
| 第三阶段 | `[牛6]` |

常规路线顺带生成（= 数组前序），`onPick` 全路线统一按链写，无分支代码。

2. **写入层**：覆盖 → 链式合并，v2 补「回调重走覆盖」分支：

```js
const chain = collectPrevChain(stage);   // 沿 prev_stage_ids 递归收集
const old = checkin.getCompletedStages();
if (old.indexOf(stage.stage_id) >= 0) {
  checkin.setCompletedStages(chain);     // 回调重走：覆盖为当前链，旧标记不残留
} else {
  checkin.setCompletedStages(            // 前进/支线汇合：合并保留走过的标记
    Array.from(new Set([...old, ...chain]))
  );
}
```

四种路径验证：直达用户选牛4 → 只标 {前置,一}，支线干净；切入用户选调整牛2 → 牛1 不标（符合切入语义）；支线用户走完牛1→牛2 汇合选牛4 → 调整标记全部保留；**回调重走（v2 补）**：从二阶段切回前置阶段 → 名单覆盖为空，前置/一的勾随之清除（初版纯合并会残留，仅影响展示）；误选三阶段改回牛4 → 残留的牛5/牛6/三阶段标记同样被覆盖清除。常规路线行为零变化。

3. **展示层**：route 页对支线小段（`optional`）豁免 locked，节点用中性虚线圆圈；名称旁加「可选」文字徽标（stagePicker 列表同步加）。

### 6.3 已知瑕疵与兼容性

- **误选残留**（合并语义引入的唯一瑕疵）：误选高阶阶段后再改选，多余标记残留，影响仅展示层。暂不做「取消完成」入口，有用户反馈再加。
- settings 导入备份的并集合并（settings.js:556）、清除单阶段数据联动移名单（checkin.js:888）均与合并语义天然兼容，零改动。
- `stress-test.js:180` 直接调用 `setCompletedStages`，语义变化需同步断言。

### 6.4 可选标识：文字徽标而非图标（已拍板）

- 「可选」是属性不是状态，不进入节点图标状态体系（current/done/locked 各占一个 iconfont）；
- 零资源依赖（不扩 iconfont 字体），纯 CSS + 文字，颜色走变量，深色模式自动跟随，视觉权重低调。

## 七、实施顺序建议

1. `utils/data.js`：路线注册表 + 大循环拍平转换（含字段映射、双轨统一、prev 链、熏听占位）
2. `utils/checkin.js`：`LISTENING_FACTORS` 合并扩表 + tip 文案 + current_stage 路线槽位
3. 11 页接线：`routeData.stages` → `getCurrentRoute().stages` 机械替换（records 过滤、stats 选择器、settings 入口 toast）
4. `stagePicker`：链式合并写入 + 支线徽标 + 快照字段补齐
5. `route`：支线可选态 + 徽标 + meta 字段断裂修复
6. `clearPicker`：「当前路线全部数据」档
7. `stress-test.js` 同步 + 全链路回归（切路线 → 打卡 → 记录 → 统计 → 补录 → 编辑 → 清除）

## 九、风险与注意事项

- **factor 固化机制**：熏听系数调整只影响新记录，历史记录口径不变——调表前需知会。
- **累计口径提示**（`stagePicker.js:46-48` 注释）：现有「前序只写 completed 标记、不补时长」行为在链式方案下保留；常规路线 400H/480H 累计判定不受影响。大循环三阶段晋级无累计口径，同样不受影响。
- **老用户兼容**：`current_route` 默认 regular、记录零迁移、completedStages 混存，全部路径对存量数据无感。
