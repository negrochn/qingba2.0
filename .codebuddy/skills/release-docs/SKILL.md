# 发布文档更新（CHANGELOG + README）

发布一个新版本时，按以下顺序更新文档。版本信息**不写入代码**——设置页「关于小程序」读线上版本号（`wx.getAccountInfoSync`），仓库无版本常量需要改。

## 1. CHANGELOG.md 正文条目

在文件头部、上一个版本条目**之前**插入：

```markdown
## [X.Y.Z] - YYYY-MM-DD

> 一句话导语：点名本版本主题与最核心的用户可感知变化。

### 新增

- **功能名（`pages/xxx` + `utils/xxx.js`）**：行为与口径细节——条件、默认值、边界、与既有语义的对应关系

### 变更 / ### 修复 / ### 移除

- 同上风格；无内容的段落整体省略
```

- 日期取当天（`YYYY-MM-DD`）
- 条目面向**用户视角**（功能、行为、口径），文件路径只在开头括号出现一次
- 风格为 Keep a Changelog 中文 1.1.0；动笔前先读文件内最近两个版本条目对齐详略与语气（本项目条目偏细：单条目可整段长句展开，含设计取舍）

## 2. CHANGELOG.md 文末「## 发布版本」表

文件末尾有发布摘要表（发布页用），在表头 `| ---- | ---- |` 下插入新版本行：

```markdown
| X.Y.Z | 单行摘要，≤95 字，句号结尾。 |
```

- 说明是**面向用户的单行摘要**：版本主题 + 各功能群各一句话；不写文件名、不写实现细节
- 字数**必须 ≤95**（含标点），写完数一遍
- 格式参照表内最近几行（如 4.8.0、4.4.0 行）

## 3. README.md「项目结构」段核对

版本涉及页面 / 工具 / 样式增删时，核对目录树并同步（此段历史上有滞后欠账，务必逐项对）：

- 新页面：`pages/` 段按功能序插入一行，注释写清页面职责与入口
- 下线页面：删除对应行（同时确认「技术栈」等段落无残留引用）
- 新增公共样式：`styles/` 段补行
- 新增工具：`utils/` 段补行，注释一句话职责
- 新增静态资源目录：`images/` 段补行
- 「技术栈」段口径（如图表类型、字体方案）与实际一致

## 4. 发布前仓库卫生

- 检查 `git status`：备份产物 / 临时文件（如根目录的 docx 导出物）不得混入待提交清单
- `.codebuddy/` 下的变更不属于业务提交范围，提交时提醒用户剔除
