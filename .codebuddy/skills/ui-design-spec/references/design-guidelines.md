# 微信小程序设计指南（design-guidelines.md）

> 来源：微信官方《小程序设计指南》（https://developers.weixin.qq.com/miniprogram/design/）。
> 该指南偏「原则与交互规范」，视觉令牌（色彩/字体/列表/表单/按钮/图标）仅给标题，统一以 WeUI 为本 skill 权威来源（见 `design-tokens.md`）。
> 可量化的硬性指标已并入 `design-tokens.md` §7；本节沉淀原则、导航、反馈、层级等**非数值规范**。

---

## 一、四大设计原则（用户体验目标：友好、高效、一致）

1. **友好礼貌**
   - 1.1 重点突出：每页明确重点，剔除无关干扰元素。
   - 1.2 流程明确：操作流程中不打断用户目标。
2. **清晰明确**
   - 2.1 导航明确，来去自如：告知用户「所在 / 可去 / 如何回退」。
   - 2.2 减少等待，反馈及时：加载与操作结果均需及时反馈。
   - 2.3 异常可控，有路可退：异常状态明确提示原因与解决方案（如表单报错）。
3. **便捷优雅**
   - 3.1 减少输入：调用摄像头 / 地理位置等接口，或提供历史选项代替键盘输入。
   - 3.2 避免误操作：手指点击精度低，保证热区面积（≥ 88rpx，见 `design-tokens.md` §7）。
   - 3.3 利用接口提升性能：使用 WeUI 标准控件库与微信公共库。
4. **统一稳定**：跨页面统一控件与交互方式，降低学习成本，推荐使用微信标准控件。

## 二、视觉规范要点（指向 WeUI）

| 维度 | 指南说明 | 落地依据 |
|---|---|---|
| 字体 | 与运行系统字体保持一致；常用字号 22/17/15/14/12 pt | `design-tokens.md` §2、§7 |
| 色彩 | 文字用色 / 彩色色板；小程序菜单深浅两套配色 | `design-tokens.md` §1（BG/FG/BRAND/RED/LINK） |
| 列表 | 仅标题，无展开 | `components.md` 原语 1–3（cells / cell / 标题） |
| 表单 | 仅标题，无展开 | `components.md` 原语 5（form） |
| 按钮 | 仅标题，无展开 | `components.md` 原语 4（button） |
| 图标 | 尺寸参考 WeUI 基础控件库 / 开发文档 | 本项目 iconfont（见 `components.md` 原语 11） |

## 三、导航规范

- **小程序菜单（官方控件）**：所有页面右上角固定位置，微信统一放置，开发者不可自定义内容与文案；提供深浅两套配色。设计需预留该区域空间，避免右上角附近的交互冲突。
- **页面内导航**：开发者可自建导航，但应与官方样式有差异；次级页左上角应提供返回操作（iOS 边缘右滑 / 安卓物理返回键）。
- **标签分页栏（Tab）**：可固定顶部或底部；数量 **不得少于 2 个、最多不得超过 5 个，建议 ≤4 项**；首页可选微信原生底部标签分页（自定义图标 / 文案 / 颜色）；顶部标签栏颜色可自定义但须保证可用性。

## 四、反馈规范

### 加载
- 启动页加载：微信统一提供 Logo + 加载状态，不可改。
- 下拉刷新：微信标准样式。
- 页面内加载：可自定义，须简洁 + 简单动画；**局部加载优先**（页面跳动小）。
- 模态加载：覆盖全页、易引发焦虑，谨慎使用（仅全局性操作）。
- 全局加载：标题栏提示。
- 加载注意：长时间载入需提供**取消操作 + 进度条**；保持动画；**同页不超过 1 个加载动画**。

### 结果反馈（层级由低到高）
- 局部操作：在操作区直接反馈。
- 图标型弹出：轻量成功提示，**1.5 秒自动消失**；不适用错误提示。
- 文字型弹出：轻量解释 / 不严重错误，**1.5 秒消失**。
- 模态对话框：需用户明确知晓，带下一步指引（见 `components.md` 原语 8）。
- 结果页：流程终结的强烈告知。

---

## 五、异常与层级

- **异常可控**：表单报错在顶部告知原因，并标识错误字段（原位 / 公告 / 模态报错三选一）；杜绝用户「无处可退」。
- **层级**：
  - 模态层（如模态加载 / 模态对话框 / 结果页）：覆盖全页、阻断式、高层级。
  - 弹出提示（toast / 局部反馈）：低层级，不打断流程。

---

## 六、自检清单（落地前对照）
- [ ] 每页是否有明确重点，无无关干扰元素？
- [ ] 用户能否清楚「在哪 / 能去哪 / 怎么回退」？
- [ ] 可点项热区 ≥ 88rpx（避免误触）？
- [ ] 是否优先用 WeUI 标准控件（列表 / 按钮 / 开关 / 弹窗）？
- [ ] 加载是否局部优先、同页 ≤1 动画、长任务有取消 + 进度？
- [ ] 成功 toast 1.5s、错误不滥用图标型弹出？
- [ ] 颜色 / 字号 / 间距是否只引用 token（无硬编码）？
